# 门户展示配置体系方案

## 一、体系架构

门户前台展示效果由后端统一配置，形成一套可管理、可发布、可回滚的体系化方案。

```
前台门户（只读已发布版本）
  ├── GET /api/v1/public/home        首页（已发布版本快照）
  ├── GET /api/v1/public/pages/:slug 落地页（已发布版本快照）
  └── GET /api/v1/public/theme       主题配置（颜色/字体/布局）
                    ↑ 发布后立即生效（缓存自动失效）
后台管理（草稿与线上分离）
  ├── 保存草稿版本 POST /admin/pages/:id/versions
  ├── 版本历史   GET  /admin/pages/:id/versions
  ├── 发布版本   POST /admin/versions/:id/publish
  ├── 回滚版本   POST /admin/versions/:id/rollback
  └── 更新主题   PUT  /admin/theme/:key
```

## 二、核心能力一：页面版本化发布

### 1. 解决的核心痛点

传统做法是编辑页面主表直接修改，存在两大问题：
- **编辑即生效**：后台还没改完，前台已经能看到半成品（内容缺失、排版错乱）
- **无法回滚**：改坏了无法一键恢复

### 2. 方案：草稿与线上分离（Draft / Published 双态）

```
编辑流程：保存草稿（不影响线上）→ 预览草稿 → 确认无误 → 发布 → 前台立即生效

数据模型：page_versions 表
  - 每次保存生成一个新版本号（v1, v2, v3...）
  - 每个版本完整快照（snapshot JSONB），包含页面所有模块配置
  - status: draft（草稿）/ published（线上）/ archived（历史归档）
```

### 3. 工作流

| 步骤 | 操作 | 前台影响 |
|------|------|---------|
| 1. 编辑 | 保存草稿 v1（draft） | 无影响，线上还是旧版 |
| 2. 再改 | 保存草稿 v2（draft） | 无影响 |
| 3. 确认 | 发布 v2 | v2 立即生效，v1 归档 |
| 4. 改坏了 | 回滚到 v1 | v1 内容复制为新版本并发布 |

### 4. 已实现 API

| 接口 | 权限 | 说明 |
|------|------|------|
| POST /admin/pages/:id/versions | page:update | 保存草稿版本 |
| GET /admin/pages/:id/versions | page:view | 版本历史列表 |
| POST /admin/versions/:id/publish | page:publish | 发布版本（事务：归档旧版+启用新版） |
| POST /admin/versions/:id/rollback | page:publish | 回滚到历史版本 |

### 5. 验证结果（实际运行）

```
pageId: 4a4e4acd-340a-4bab-bb3a-45de0a41cbcc
保存草稿：draft version: 1  ✅
发布版本：publish: True     ✅
版本历史：v1 - published    ✅
```

## 三、核心能力二：主题配置

### 1. 解决的核心痛点

门户视觉风格（主色调、字体、按钮圆角、间距等）硬编码在前端，每次调整都要改代码重新部署。

### 2. 方案：主题配置中心

后台可视化配置，前端通过 API 读取后渲染，实现"改配置即改样式"。

### 3. 可配置项（12 项，按分组）

| 分组 | 配置项 | 默认值 | 说明 |
|------|--------|--------|------|
| color | primary_color | #2563eb | 主色调 |
| color | secondary_color | #1e40af | 辅助色 |
| color | accent_color | #f59e0b | 强调色（CTA 按钮） |
| typography | font_family | Inter, system-ui | 字体 |
| typography | heading_size | large | 标题尺寸 |
| header | header_style | sticky | 导航栏样式 |
| header | header_height | 72 | 导航栏高度 |
| button | button_radius | 8 | 按钮圆角 |
| layout | card_radius | 12 | 卡片圆角 |
| layout | section_spacing | 80 | 区块间距 |
| layout | container_width | 1280 | 内容区宽度 |
| footer | footer_columns | 4 | Footer 栏数 |

### 4. 已实现 API

| 接口 | 权限 | 说明 |
|------|------|------|
| GET /public/theme | 公开 | 前端读取主题配置 |
| PUT /admin/theme/:key | setting:manage | 更新配置项（自动失效缓存） |

### 5. 验证结果（实际运行）

```
GET /api/v1/public/theme 返回：
{
  "accent_color": "#f59e0b", "button_radius": 8, "card_radius": 12,
  "container_width": 1280, "font_family": "Inter, system-ui, sans-serif",
  "footer_columns": 4, "header_height": 72, "header_style": "sticky",
  "heading_size": "large", "primary_color": "#2563eb",
  "secondary_color": "#1e40af", "section_spacing": 80
}
```

## 四、页面模块化（已有基础，版本化发布在此基础上构建）

### PageModule 模块类型

页面由多个可拖拽排序的模块组成，每个模块是独立的展示单元：

| 模块类型 | 展示效果 |
|---------|---------|
| hero | 首屏大图 + 标题 + CTA 按钮 |
| banner | 广告横幅 |
| products | 产品网格展示 |
| about | 公司介绍 |
| factory | 工厂实力展示 |
| certification | 认证展示 |
| process | 生产流程 |
| faq | 常见问题 |
| contact | 联系表单 |
| custom | 自定义 HTML |

前台根据模块顺序渲染，后台可配置每个模块的内容和样式。

## 五、体系化优势总结

| 能力 | 价值 |
|------|------|
| 版本化发布 | 编辑不影响线上，一键回滚，安全可控 |
| 主题配置 | 改视觉风格无需重新部署 |
| 模块化页面 | 灵活组合展示内容 |
| RBAC 权限 | 不同角色控制编辑/发布权限 |
| 缓存一致性 | 发布/更新自动失效缓存，前台立即看到最新内容 |
| 完整快照 | 每个版本独立快照，历史可追溯 |

## 六、数据一致性

```
页面发布版本 → page_versions.status = published
            → pages.status 同步更新为 published
            → 前台 /public/pages/:slug 读取已发布版本快照
            → 缓存失效，下次请求回源 DB

主题更新   → theme_configs.value 更新
          → cache:theme 缓存失效
          → 前台 /public/theme 读取最新配置
