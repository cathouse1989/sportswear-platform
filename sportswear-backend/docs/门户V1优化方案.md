# 门户 V1 优化方案（B2B 架构重组 + 全球统一品牌视觉）

> 版本：v1.0（草案）
> 范围：门户前台 + 管理后台（门户预览/主题配置）+ 后端服务
> 前置文档：《门户展示配置体系.md》《国际化优化实施计划.md》

---

## 一、背景与目标

门户当前是"产品目录式"结构（`/products` 为主线），对 B2B 服装 OEM/ODM 外贸的转化效率不足：
采购决策链上"能力验证 → 场景匹配 → 知识调研 → 询盘"四个环节，门户只覆盖了"产品展示"一个环节。

V1 优化的两大目标：

1. **B2B 架构重组**：借鉴 Protolabs（能力/工艺架构）+ Xometry（询盘逻辑）+ 时尚品牌（视觉），
   把门户升级为"能力证明 + 场景入口 + 内容获客"三支柱结构，唯一转化出口是 Request a Quote。
2. **全球统一品牌视觉 + 语言本地化**：参考 Aritzia 等成熟国际时尚品牌的设计方法，建立一套全球一致的品牌色与设计 Token；门户只按语言切换文案、内容和 SEO，不按国家或地区改变品牌视觉。

**明确不做（V1 边界）**：
- 不新做询盘系统（`Lead` 询盘闭环已完整）；
- 不新增后端 API 路由（全部基于现有接口，向后兼容）；
- 不动门户技术栈（Nuxt 3 + Tailwind + @nuxtjs/i18n 保持不变）。

### 2.2 需要补齐的缺口

| 缺口 | 现状 | 影响 |
|------|------|------|
| 主题色未应用到门户 | 后台配置的 `primary_color`/`secondary_color`/`accent_color` 存库后，门户仅使用 `logo_url`/`social_*`/`favicon_url`，**颜色硬编码在 Tailwind 类**（如 `bg-[#0D1B2A]`、`text-[#D4A853]`） | 改主题色无任何视觉效果 |

| 内容页缺失 | Manufacturing/Industries/Resources 页面未建立 | 搜索流量入口不足 |

## 七、P4：全球统一品牌视觉系统

> 决策变更：V1 不建设国家、地区或市场维度的主题系统。品牌视觉全球统一，门户只按语言切换文案、内容和 SEO。

### 7.0 参考原则

Aritzia 国际站对自动抓取返回 HTTP 403，因此本方案不声称复刻其当前精确色值或组件细节。这里只参考成熟国际时尚品牌普遍验证过的方法：

1. **全球视觉一致**：Logo、主色、字体、按钮和空间体系不随语言变化；
2. **中性底色承载商品**：暖白/米色背景、深色正文、低饱和边框，让服装图片成为视觉主体；
3. **强调色克制**：强调色只用于主要 CTA、选中态和关键提示，避免大面积铺色；
4. **层级依赖排版与留白**：通过字号、字重、间距、图片比例建立高级感，而不是依赖多种亮色；
5. **只做语言本地化**：切换语言时更新 UI 文案、页面内容、导航和 SEO，品牌色与组件体系保持不变。

> 参考不等于照抄：不得复制 Aritzia 的专有素材、文案、页面编排或未核实的精确色值；最终视觉必须服务于“服装 OEM 制造可信度 + B2B 询盘转化”。

### 7.1 全球品牌 Token

#### 7.1.1 建议视觉方向

沿用当前门户已有的暖中性色基础并规范化：

| Token | 建议初始值 | 用途 |
|-------|------------|------|
| `brand.ink` | `#0D1B2A` | 标题、深色区、Logo 主体 |
| `brand.gold` | `#D4A853` | 主 CTA、选中态、少量强调 |
| `surface.page` | `#FBF9F6` | 页面主背景 |
| `surface.card` | `#FFFFFF` | 卡片、导航、表单 |
| `text.primary` | `#1A1A1A` | 正文与标题 |
| `text.muted` | `#6F6A63` | 次级说明 |
| `border.subtle` | `#EAE5DD` | 分割线和边框 |
| `state.*` | 独立功能色 | 成功、警告、错误，不纳入品牌换色 |

该色值为 V1 初始基线，发布前需要结合真实产品图和 WCAG 对比度做视觉评审。

#### 7.1.2 后端范围

- 保留现有 `ThemeConfig` 单 key 全局模型，不增加国家、地区或语言维度，不调整数据库唯一索引；
- 保留现有 `/public/theme`、`/admin/theme`、`PUT /admin/theme/:key` 接口；
- 保留单一 `cache:theme` 缓存键和现有失效逻辑；
- 扩充全局主题项，使其覆盖背景、文本、边框、按钮、圆角、字体与间距等语义 Token；
- 对颜色、数字、枚举值执行后端白名单与格式校验，防止无效配置进入门户。

#### 7.1.3 主题发布治理

- V1 仍使用全局主题配置，但保存前必须展示影响范围与二次确认；
- 管理后台提供对比度检查和门户预览；
- 操作继续进入现有 Audit 审计日志；
- 后续如需要换季活动，只允许通过“活动 Banner/素材”表达，不修改核心品牌 Token；
- 若未来确需多品牌运营，应引入独立 Brand/Tenant 维度，而不是跟随语言切换品牌色。

### 7.2 门户改造

#### 7.2.1 CSS 变量基座：`sportswear-portal/assets/css/main.css`

```css
:root {
  --brand-ink: #0d1b2a;
  --brand-accent: #d4a853;
  --surface-page: #fbf9f6;
  --surface-card: #ffffff;
  --text-primary: #1a1a1a;
  --text-muted: #6f6a63;
  --border-subtle: #eae5dd;
}
```

主题 API 与 CSS 变量建立固定白名单映射；所有页面只能消费语义 Token，不直接绑定数据库 key，也不允许任意字符串进入样式。

#### 7.2.2 全局主题加载：`sportswear-portal/composables/useTheme.ts`（新建）

- SSR 拉取一次 `/public/theme`，在首屏应用全局 Token，减少颜色闪烁；
- API 失败时使用 CSS 内置默认值，不影响页面和询盘；
- 客户端只在全局主题配置更新或预览刷新时重新加载；
- 语言变化只刷新对应翻译和内容，不触发品牌 Token 变化。

#### 7.2.3 Tailwind 语义色

在 `sportswear-portal/nuxt.config.ts` 中把 Tailwind 颜色映射至 CSS 变量，例如：

```ts
colors: {
  ink: 'var(--brand-ink)',
  accent: 'var(--brand-accent)',
  'surface-page': 'var(--surface-page)',
  'surface-card': 'var(--surface-card)',
  'text-primary': 'var(--text-primary)',
  'text-muted': 'var(--text-muted)',
  'border-subtle': 'var(--border-subtle)',
}
```

#### 7.2.4 硬编码颜色替换

| 文件范围 | 处理方式 |
|----------|----------|
| `layouts/default.vue` | 公告条、导航、CTA、Footer 改用品牌 Token |
| `components/SportswearLogo.vue` | SVG 改用 `currentColor` 和品牌 Token |
| `pages/**/*.vue`、`components/**/*.vue` | 背景、标题、按钮、边框替换为语义类 |
| 功能状态色 | success/warning/error 独立管理，不与品牌强调色混用 |

必须检查 WCAG 2.1 AA：普通文本至少 4.5:1，大文本至少 3:1。

### 7.3 管理后台改造

#### 7.3.1 门户预览：`sportswear-admin/src/views/portal/preview.vue`

- 保留现有语言、设备、横竖屏和页面选择，不新增国家或市场选择器；
- 切换语言后，iframe 路径、动态词条、页面内容和 SEO 预览同步更新；
- 所有语言必须显示同一套品牌 Token；
- 增加长文案溢出、按钮宽度、导航换行和 RTL 预留检查。

#### 7.3.2 主题配置：`sportswear-admin/src/views/system/theme.vue`

- 删除区域筛选和区域覆盖概念；
- 按「品牌 / 表面 / 文本 / 边框 / 字体 / 布局」分组管理全局 Token；
- 增加实时色板、组件示例、桌面/移动端预览和 WCAG 对比度检查；
- 核心品牌色保存前二次确认并记录审计日志；
- 提供“恢复品牌基线”能力，防止长期运营造成视觉漂移。

#### 7.3.3 API 封装

沿用现有接口，不增加 country 参数：

```ts
export const themeApi = {
  get: () => http.get('/public/theme'),
  adminList: () => http.get('/admin/theme'),
  update: (key: string, value: unknown) =>
    http.put(`/admin/theme/${key}`, { value }),
}
```

## 八、数据流与回退策略

### 8.1 线上访客

```text
门户 SSR → GET /public/theme → 应用全球品牌 Token
访问 /en、/zh、/es、/fr → 按语言加载词条、页面内容和 SEO
用户切换语言 → URL 与本地化内容同步更新
品牌 Token → 始终保持不变
```

回退链：后台全局主题 → 门户 CSS 内置品牌基线。主题 API 异常不能阻塞页面、内容或询盘。

### 8.2 后台预览

```text
管理员选择 en/zh/es/fr → iframe 打开对应语言路径
                        → 验证词条、页面内容、SEO 与排版
                        → 所有语言继续使用同一套全球品牌 Token
```

### 8.3 缓存约定

- 沿用现有单一 `cache:theme`；
- 更新任一全局主题项后删除该缓存键；
- 主题缓存不按国家、地区或语言拆分；
- 门户预览可通过现有刷新时间戳和主题更新后的缓存失效获取最新全局视觉。

## 十一、风险、治理与回滚

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 机械照抄参考品牌 | 缺少自身识别度并存在知识产权风险 | 只借鉴一致性、留白和克制原则，不复制素材、文案和页面编排 |
| 主题 Token 过多 | 运营随意调整造成视觉漂移 | V1 控制 Token 数量，核心品牌色受保护并可恢复基线 |
| 主题色对比度不足 | 可访问性和转化下降 | 后台保存/发布前自动计算 WCAG 对比度 |
| SSR 首屏颜色闪烁 | 体验不一致 | SSR 预取主题；CSS 默认值与全局主题保持一致 |
| URL/导航一次变化过大 | SEO 排名与旧链接损失 | URL 定稿后建立 301 映射；canonical 与 sitemap 同步 |
| 内容页只有营销空话 | SEO 与信任效果弱 | 强制真实工厂素材、参数、流程、交期、案例与证据 |
| 语言状态与品牌主题耦合 | 切换语言时错误换色或重复加载主题 | 代码层分离 Locale 与 Theme 状态，并加入多语言回归测试 |
| 主题配置即时影响线上 | 误操作风险 | RBAC + 审计 + 二次确认；后续升级草稿/发布/回滚 |

### 11.1 回滚策略

1. **内容/导航**：保留旧导航数据快照；新页面下线即可，旧 URL 继续可用；
2. **主题配置**：保存品牌基线快照，可一键恢复所有核心 Token；
3. **数据库**：不新增区域字段与索引，无额外数据库结构回滚；
4. **代码**：门户始终保留 CSS 默认品牌基线，动态主题关闭时仍可正常展示；
5. **缓存**：回滚或发布后删除现有 `cache:theme`，下次请求重新生成。

## 十二、V1 决策结论

**决定采用该方案，但按“架构先行、样板验证、内容扩展、全球品牌视觉并行”的方式实施。**

V1 的成功标准不是页面数量或视觉华丽程度，而是：

1. 采购商能快速理解“能做什么、怎么做、适合谁”；
2. Google 能识别清晰的制造、行业和知识主题簇；
3. 所有关键页面都有明确且可追踪的 Request a Quote 转化路径；
4. 门户和管理后台预览在 en/zh/es/fr 下保持统一、可访问、可回退的品牌视觉；
5. 所有变更不破坏现有产品、内容、多语言、SEO 和询盘闭环。

下一步应先完成 **P1 URL/导航清单和 3 个样板页内容框架**，待业务确认后进入代码与内容实施。
