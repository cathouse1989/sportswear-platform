# 门户网页管理 + 后台多语言支持 — 方案 v1

> 项目：sportswear-admin (Vue 3 + Vite + Element Plus + Pinia + TypeScript)  
> 状态：规划阶段 | 作者：Cline | 日期：2026-08-26

---

## 1. 现状分析

### 1.1 项目技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Vue 3.5 + Vite 6 |
| 语言 | TypeScript ~5.6 |
| UI 组件 | Element Plus 2.9 |
| 状态管理 | Pinia 2.3 |
| 路由 | Vue Router 4.5 |
| HTTP 客户端 | Axios 1.7 |
| 国际化 | **暂无 vue-i18n，仅 Element Plus zh-cn 静态加载** |

### 1.2 门户内容管理现状 (CMS)

当前门户网页内容管理被拆分到 `src/views/cms/` 目录下的 7 个 Vue 文件中，但缺乏统一规范：

| 视图文件 | 管理对象 | API 来源 | CRUD | 发布/下线 | 分页 | 问题 |
|---------|---------|---------|------|---------|------|------|
| `pages.vue` | 单页面 (Home, Product, OEM 等) | `pageApi` (index.ts) | ✅ | ✅ | ✅ 服务端 | 无模块编辑、无翻译编辑、Page.modules/translations 字段未使用 |
| `blogs.vue` | 博客文章 | `cmsApi` (cms.ts) | ✅ | ✅ (在 index.ts 的 blogApi) | ✅ 服务端 | cms.ts 缺少 publish 接口 |
| `cases.vue` | 案例 | `cmsApi` (cms.ts) | ✅ | ❌ | ✅ 服务端 | 无发布/下线 |
| `faqs.vue` | 问答 | `cmsApi` (cms.ts) | ✅ | ❌ | ✅ 服务端 | 有 `language` 列，无按语言过滤 |
| `factories.vue` | 工厂 | `factoryApi` (index.ts) | ✅ | ✅ | ❌ 客户端 | 分页逻辑重复 |
| `certifications.vue` | 认证 | `certificationApi` (index.ts) | ✅ | ✅ | ❌ 客户端 | 分页逻辑重复 |
| `production-processes.vue` | 生产流程 | `productionProcessApi` (index.ts) | ✅ | ✅ | ❌ 客户端 | 分页逻辑重复 |

**重复 API**：`api/index.ts` 中的 `pageApi` 与 `api/cms.ts` 中的 `cmsApi.pages` 完全重复，同 URL `/admin/pages`：

```ts
// index.ts
export const pageApi = { list, get, create, update, delete, publish, unpublish }

// cms.ts
export const cmsApi = {
  pages: { list, get, create, update, delete, publish, unpublish }  // 完全重复
}
```

**未接入的 API**：`src/api/index.ts` 中已定义但**没有对应视图**的 API 包括：
- `navigationApi` (`/admin/navigations`) — 导航管理
- `portalApi` (`/admin/pages/:id/versions`, `/admin/versions/:id/publish`, `/admin/versions/:id/rollback`) — 页面版本管理 (草稿/发布回退)

**类型缺口**：`types/index.ts` 中定义了 `PageModule`、`PageTranslation`、`BlogTranslation`、`CaseTranslation` 等结构，但 CMS 视图从未使用这些字段，意味着**多语言内容编辑和模块编排功能缺失**。

### 1.3 后台多语言现状

| 层级 | 当前状态 |
|------|---------|
| Element Plus 语言包 | `App.vue` 硬编码加载 `zhCn`，无法切换 |
| 后台 UI 字符串 | 全部硬编码为中文 (sidebar、表单 placeholder、按钮文字、提示语等) |
| i18n 词条管理 | `system/i18n.vue` 已有词条 CRUD (key/language/value/module)，但仅用于**门户前端**词条 |
| 后台用户语言偏好 | 无记录机制 — 用户无法设置界面语言 |
| 语言等级 | 仅 `en / zh / es / fr` 出现在前端下拉 (i18n.vue 和 portal preview.vue) |

### 1.4 门户预览现状

`views/portal/preview.vue` 已具备基本能力：
- 语言下拉 (从 `/public/languages` 获取)
- 页面下拉 (home/products/cases/blogs/faqs/factories/certifications/processes)
- `t()` 函数从 `/public/i18n?lang=xx&preview=1` 获取词条字典
- `preview=1` 参数保证直查 DB，绕过缓存

## 2. 目标

### 2.1 门户网页管理目标

1. **统一 CMS API**：消除 `pageApi` / `cmsApi` 重复，统一入口
2. **页面内容编辑器 (Page Builder)**：支持拖拽式模块编排 × 多语言翻译编辑
3. **页面版本管理**：支持草稿保存、版本列表、发布回退
4. **导航管理**：前台导航菜单的 CRUD 管理
5. **标准化 CRUD 模板**：所有 CMS 视图遵循统一的列表 / 表单 / 发布模式

### 2.2 后台多语言目标

1. **安装 vue-i18n**：集成官方国际化插件
2. **管理后台多语言包**：en / zh / es / fr，覆盖所有 UI 字符串
3. **后台语言选择器**：在-header 右侧添加语言下拉，切换立即生效
4. **Element Plus 动态语言包**：同步切换组件内置文案 (分页、日期等)
5. **用户语言偏好**：记录当前用户选择的语言到 localStorage，默认跟随浏览器 or 回退为 en

```typescript
import { setLocale } from '@/locales'
import { supportedLanguages } from '@/locales/languages'
import { useI18n } from 'vue-i18n'

const { locale } = useI18n()
const currentLangCode = computed(() => locale.value)
const currentLangNativeName = computed(() => {
  const l = supportedLanguages.find(x => x.code === locale.value)
  return l?.native_name || locale.value
})

function handleLanguageChange(code: string) {
  setLocale(code)
}
```

| `pageApi` | `/admin/pages` | 页面管理 (list/get/create/update/delete/publish/unpublish) |
| `blogApi` | `/admin/blogs` | 博客管理 (补全 publish) |
| `caseApi` | `/admin/cases` | 案例管理 (补全 publish/unpublish) |

#### 3.2.5 标准化 CRUD 模板

**动机**：7 个 CMS 视图样式各异，部分客户端分页 (factories/certifications/processes)，表单结构不一致。

**方案**：创建可复用的 `composables/useCrud.ts` + `components/base/BaseCrudPage.vue`，封装：

```typescript
// src/composables/useCrud.ts
export function useCrud(api: {
  list: (params: any) => Promise<any>
  create: (data: any) => Promise<any>
  update: (id: string, data: any) => Promise<any>
  delete: (id: string) => Promise<any>
  publish?: (id: string) => Promise<any>
  unpublish?: (id: string) => Promise<any>
}) {
  const items = ref<any[]>([])
  const loading = ref(false)
  const total = ref(0)
  const page = ref(1)
  const pageSize = ref(20)
  const keyword = ref('')
  const dialogVisible = ref(false)
  const editingId = ref('')

  const loadData = async (extraParams = {}) => {
    loading.value = true
    try {
      const result = await api.list({
        page: page.value, pageSize: pageSize.value,
        keyword: keyword.value, ...extraParams
      })
      items.value = result.items || result || []
      total.value = result.total ?? items.value.length
    } finally { loading.value = false }
  }

  async function handleSave(form: any) {
    try {
      editingId.value
        ? await api.update(editingId.value, form)
        : await api.create(form)
      ElMessage.success('common.save_success')
      dialogVisible.value = false
      loadData()
    } catch {}
  }

  async function handleDelete(row: any) {
    await ElMessageBox.confirm(
      'common.delete_confirm', 'common.confirm', { type: 'warning' }
    )
    await api.delete(row.id)
    ElMessage.success('common.delete_success')
    loadData()
  }

  async function handlePublish(row: any) {
    await api.publish!(row.id)
    ElMessage.success('common.publish')
    loadData()
  }

  return { items, loading, total, page, pageSize, keyword,
           dialogVisible, editingId, loadData, handleSave, handleDelete, handlePublish }
}
```

**统一后的 CMS 视图迁移**：

| 视图 | 当前缺陷 | 标准化改造 |
|------|---------|-----------|
| `pages.vue` | 无模块编辑 | 加入 3 个页签 (基础/模块/翻译) |
| `blogs.vue` | cms.ts API | 切至 `blogApi`，补充 publish |
| `cases.vue` | 无发布 | 补充 publish/unpublish |
| `faqs.vue` | 无发布 | 补充 publish/unpublish + 语言筛选 |
| `factories.vue` | 客户端分页 | 切换服务端分页，接入 `useCrud` |
| `certifications.vue` | 客户端分页 | 切换服务端分页，接入 `useCrud` |
| `production-processes.vue` | 客户端分页 | 切换服务端分页，接入 `useCrud` |

> **注意**：`factories`、`certifications`、`production-processes` 当前不支持 `publish/unpublish` 在 `cms.ts` 中，因为它们通过 `factoryApi`、`certificationApi`、`productionProcessApi` (在 `index.ts` 中) 管理，已有发布接口。改造时统一为服务端分页。

#### 3.2.6 门户与后台 i18n 词条联动

**目标**：门户前端的 i18n 词条 (`system/i18n.vue` 管理的 `I18nEntry`) 与后台 admin UI 的 i18n **解耦**，但共享语言列表。

| 语言资源 | 管理位置 | 用途 |
|----------|---------|------|
| 后台 UI 文案 | `src/locales/{lang}/index.ts` (git tracked) | 管理员界面 |
| 门户前端文案 | 数据库 `i18n_entries` 表 (via `i18nApi`) | 访客门户界面 |
| 语言列表 | `/public/languages` API + `supportedLanguages` | 共享 |

**为什么解耦**：
- 后台 UI 文案属于**开发者**层级，随代码发布
- 门户前端文案属于**内容运营**层级，由 `system/i18n.vue` 在线编辑
- 避免运营编辑门户文案时影响后台界面

**共享**：语言列表 (en/zh/es/fr) 在两个系统间保持一致。

## 5. 风险与注意事项

| 风险 | 缓解措施 |
|------|---------|
| **硬编码中文过多，替换工作量大** | 按优先级分批 (P0→P4)，先实现 i18n 基础设施再逐页迁移 |
| **门户预览 `t()` 是本地函数，与 vue-i18n 冲突** | 门户预览 (`portal/preview.vue`) 使用本地 `t()`，**不受影响**；仅后台 Admin UI 使用 vue-i18n |
| **API 重复删除可能影响其他分支** | 确认所有视图均迁移到 `api/index.ts` 后再删除 `cms.ts` |
| **模块编辑器复杂度高** | v1 先实现基本的模块列表 + 排序 + 类型切换，后续迭代富文本编辑器 |
| **版本管理回退需谨慎** | 发布/回退操作需二次确认 + 记录操作日志 |
| **Element Plus 语言包体积** | 使用按需引入 + CDN 外链降低打包体积 |
| **服务端分页改造可能需后端配合** | factories/certifications/processes 目前客户端分页，后端 API 应已支持分页参数 |
