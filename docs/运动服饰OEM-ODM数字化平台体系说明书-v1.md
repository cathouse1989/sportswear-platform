# 运动服饰 OEM/ODM 数字化平台 · 体系说明书（客户版）

> 版本：v1.1　整理日期：2026-09-07　整理人：**Eric Lee**
> 面向对象：客户业务/决策方（非技术读者）
> 说明：本文用业务语言说明系统「是什么、由什么组成、能做什么、如何交付」。

## 一、平台定位与价值

### 1.1 定位一句话
一套面向运动服饰 OEM/ODM 出海业务的数字化平台，把「产品展示 → 能力证明 → 内容获客 → 询盘转化」串成一条完整的线上获客闭环。

### 1.2 解决什么问题
- **获客**：SEO 友好的多语言门户，让全球采购商能被搜索到、能找到你；
- **信任**：系统化展示工厂、认证、生产流程、客户案例，建立专业可信形象；
- **转化**：全站唯一转化出口「Request a Quote」，所有询盘统一进入后台管理；
- **效率**：产品、内容、页面全部后台可维护，运营人员无需改代码即可完成日常更新。

### 1.3 服务对象
| 角色 | 使用端 | 主要诉求 |
|---|---|---|
| 全球 B2B 采购商 | 门户前台 | 浏览产品、了解能力、发起询盘 |
| 内部运营/内容人员 | 管理后台 | 维护产品与内容、发布上线 |
| 销售/管理员 | 管理后台 | 处理询盘、分配跟进、查看数据 |

### 1.4 商业模式闭环
```
全球采购商 ──搜索 / 点击──▶ 门户前台（四语、SEO）
                              │ 浏览产品 / 能力 / 案例
                              ▼
                       Request a Quote（询盘）
                              │
                              ▼
              管理后台 ── 询盘评分 / 分配销售 / 跟进 / 报价
```

## 二、系统总览

### 2.1 三端一体架构
```
                      全球用户（CDN / Cloudflare 加速）
                          │
     ┌────────────────────┼─────────────────────┐
     ▼                    ▼                     ▼
 门户前台              管理后台                后端 API
 (Nuxt SSR)           (Vue SPA)             (Go + Gin)
 面向全球访客          面向内部运营           双通道数据服务
     │                    │                     │
     └────────────────────┴─────────────────────┤
                                                ▼
        PostgreSQL 15（主数据库）   Redis 7（缓存）   MinIO / S3（对象存储）
```

### 2.2 三个子系统职责
| 子系统 | 面向对象 | 技术形态 | 职责 |
|---|---|---|---|
| 门户前台 | 全球访客 | SSR 服务端渲染 | 产品/内容展示、SEO、询盘 |
| 管理后台 | 内部运营 | SPA 单页应用 | 产品 + 内容 + 商机一体化管理 |
| 后端 API | 两端共用 | Go 后端服务 | 数据读写、权限控制、审计日志 |

### 2.3 端到端数据流
后台编辑（产品 / 页面 / 博客）→ 草稿 → 发布 → 门户站点实时可见；访客提交询盘 → 写入后台 → 销售跟进 / 报价。全链路数据一致、状态可控。

## 四、权限与角色

### 4.1 角色（共 9 种）
| 角色 | 职责概括 |
|---|---|
| super_admin | 平台全部权限，含用户 / 角色 / 应用管理 |
| admin | 日常全量运营 |
| content_admin | 内容运营（页面 / 博客 / 案例 / FAQ / 媒体） |

### 4.2 权限机制
- 权限码体系：`资源:动作`（view / create / update / delete / publish / manage）；
- 路由级 + 按钮级双重控制；
- 前端路由守卫 + 后端 RBAC 硬控，双保险，前端隐藏不代表后端放行。

## 五、国际化与本地化

### 5.1 多语言
- 支持语言：英语（en）、中文（zh）、西班牙语（es）、法语（fr）；
- 子路径策略：`/en/`、`/zh/`、`/es/`、`/fr/`，浏览器语言自动检测；
- 内容 / 翻译分离，支持语言回退；
- 后台提供词条、字典、翻译完成度管理，未翻译内容可追踪。

### 5.2 货币与单位
- **多货币**：货币列表 + 实时换算，前端按用户区域显示对应币种价格；
- **单位换算**：尺寸对照、尺码转换、重量单位转换。

### 5.3 SEO
- 每页独立 Title / Description；
- 自动生成 `sitemap.xml`；
- 多语言 hreflang 标签自动生成；
- SSR 服务端渲染，确保搜索引擎可抓取。

### 5.4 主题与导航配置
- 后台可配：主色 / 辅色 / 强调色、按钮样式、圆角、间距、字体；
- 导航：header / footer 两类，无限级层级；
- 页面模块化：banner、产品推荐、OEM、ODM、工厂、生产流程、案例、认证、博客、联系、图文、视频等模块自由组合。

## 六、数据与安全

### 6.1 数据模型概览（按业务分类）
| 分类 | 覆盖内容 |
|---|---|
| 用户与权限 | 用户、角色、权限、会话 |
| 多语言与字典 | 语言、词条、字典 |
| 内容管理 CMS | 页面、模块、导航、门户配置 |
| 产品管理 PIM | 产品、分类、系列、面料、规格、定制、MOQ |
| 询盘与订阅 | 询盘、跟进、报价、订阅 |
| 媒体与存储 | 图片 / 视频 / 文件、存储源 |
| 国际化 | 货币 |
| SEO 与系统 | SEO 配置、通知、操作日志、数据分析 |

### 6.2 数据安全机制
- **软删除 + 回收站**：删除先入回收站，可恢复 / 彻底删除，防止误删；
- **操作日志审计**：记录增删改、发布 / 下线、登录登出等关键动作及前后值；
- **发布状态机**：草稿 / 发布 / 下线三层状态，未发布内容前台不可见；
- **认证分级**：JWT 登录认证；API 分「公开只读 / 后台鉴权 / 应用接入」三级开放。

## 七、交付与运维

### 7.1 部署方式
- Docker Compose 统一编排，三端 + 三大基础设施一次启动；
- 提供一键部署脚本与增量更新脚本。

### 7.2 运行环境要求
| 组件 | 要求 |
|---|---|
| 容器引擎 | Docker（含 Compose） |
| 数据库 | PostgreSQL 15+ |
| 缓存 | Redis 7+ |
| 对象存储 | MinIO（本地）/ S3（生产） |

### 7.3 访问地址与默认账号
| 服务 | 地址 |
|---|---|
| 后端 API | `http://<域名>:8080` |
| 管理后台 | `http://<域名>:8090` |
| 门户前台 | `http://<域名>:3000` |
| 对象存储控制台 | `http://<域名>:9001` |
- 默认管理员：`admin@sportswear.com / Admin@123456`（生产环境务必修改）。

### 7.4 更新与回滚
- 日常更新：执行增量更新脚本；
- 数据持久化于独立数据卷，容器重建不丢数据；
- 生产域名、SEO / 分析参数（GA、站点验证、站点 URL）部署时替换为真实值。
