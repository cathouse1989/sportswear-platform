# 数据状态与软删除策略

## 一、数据状态体系

### 内容数据状态（ContentStatus）
```
draft（草稿）→ review（审核中）→ published（已发布）→ offline（已下线）→ archived（归档）
```
- 公开接口只返回 `published` 状态内容
- 后台可查看所有状态

### 翻译状态（TranslationStatus）
```
untranslated（未翻译）→ draft（草稿）→ translated（已翻译）→ pending（待审核）→ published（已发布）
```

### 询盘状态（LeadStatus）
```
new → contacted → confirmed → quoted → sampling → negotiating → won/lost
另有：spam（垃圾询盘）
```

## 二、软删除策略

### 支持软删除的数据（deleted_at 字段 + 回收站）

| 实体 | 类型 | 级联软删除的关联数据 | 删除前检查 |
|------|------|---------------------|-----------|
| 产品 product | 业务核心 | 翻译、图片、视频、规格、定制能力 | - |
| 分类 category | 业务结构 | - | ✅ 有子分类禁止删除；有产品引用禁止删除 |
| 系列 series | 业务结构 | - | - |
| 面料 fabric | 业务数据 | - | - |
| 页面 page | CMS 核心 | 模块、翻译 | - |
| 博客 blog | CMS 内容 | 翻译 | - |
| 案例 case | CMS 内容 | 翻译 | - |
| FAQ faq | CMS 内容 | 翻译 | - |
| 工厂 factory | 企业信息 | - | - |
| 认证 certification | 资质信息 | - | - |
| 生产流程 production_process | 展示内容 | - | - |
| 导航 navigation | 站点结构 | - | - |
| 媒体 media | 资源库 | - | - |
| 询盘 lead | 商业数据 | 跟进记录 | - |
| 用户 user | 系统账号 | - | - |

### 不支持软删除的数据（硬删除或保留）

| 数据 | 策略 | 说明 |
|------|------|------|
| 操作日志 operation_logs | **永久保留** | 审计要求，不允许删除 |
| 通知 notifications | 硬删除 | 已读通知可清理 |
| 报价 quotes | 软删除 | 财务相关建议保留 |
| 关联表 user_roles / role_permissions / app_users | 随主对象处理 | 解除关联即删除 |

## 三、级联删除逻辑

### 删除产品时
```
DELETE product
  ├─ 软删除 product_translations（翻译）
  ├─ 软删除 product_images（图片）
  ├─ 软删除 product_videos（视频）
  ├─ 软删除 product_specs（规格）
  └─ 软删除 product_customizations（定制能力）
全部在事务中执行，任一失败则回滚
```

### 删除页面时
```
DELETE page
  ├─ 软删除 page_modules（模块）
  └─ 软删除 page_translations（翻译）
```

### 删除博客/案例/FAQ 时
```
各自级联软删除对应翻译表
```

### 删除询盘时
```
DELETE lead
  └─ 软删除 lead_follow_ups（跟进记录）
```

### 删除分类时（引用检查）
```
1. 检查子分类：存在子分类 → 拒绝删除
2. 检查产品引用：有产品使用该分类 → 拒绝删除
3. 通过检查后执行软删除
```

## 四、回收站功能

### API 接口

| 接口 | 方法 | 说明 | 所需权限 |
|------|------|------|---------|
| /admin/trash?entity_type=product | GET | 回收站列表（可按类型过滤） | setting:manage |
| /admin/trash/:id/restore | POST | 恢复数据（含关联数据） | setting:manage |
| /admin/trash/:id/purge | POST | 彻底删除（不可恢复） | setting:manage |
| /admin/trash?entity_type=product | DELETE | 清空回收站（按类型或全部） | setting:manage |

### 使用示例

**查看回收站：**
```
GET /api/v1/admin/trash?entity_type=product&page=1&pageSize=20
```

**恢复产品：**
```
POST /api/v1/admin/trash/{id}/restore
{"entity_type": "product"}
```

**彻底删除：**
```
POST /api/v1/admin/trash/{id}/purge
{"entity_type": "product"}
```

**清空某类回收站：**
```
DELETE /api/v1/admin/trash?entity_type=blog
```

## 五、技术实现要点

1. **GORM 软删除机制**：BaseModel 包含 `DeletedAt gorm.DeletedAt`，`Delete()` 自动设置 deleted_at，普通查询自动过滤已删除记录
2. **事务保证**：级联删除在 `db.Transaction()` 中执行，任一步失败整体回滚
3. **引用检查**：分类删除前检查子分类和产品引用，防止数据孤立
4. **恢复级联**：恢复主实体时同时恢复其关联数据（翻译、图片等）
5. **Unscoped 查询**：回收站使用 `db.Unscoped()` 绕过软删除过滤器查看已删除数据
